# Open source meeting transcription workflows for a Windows laptop

Checked: 4 October 2026. Scope: recorded English, Filipino, and Taglish meetings. Local processing is preferred; Donna is out of scope. This is a **scoping comparison**, not an accuracy test. No meeting recordings, reference transcripts, or laptop specifications were supplied or used.

## Recommendation

**Fork [noScribe](https://github.com/kaixxx/noScribe) for a recorded-meeting workflow.** Its Windows builds, file queue, speaker-count control, timestamped transcript, audio-synced correction editor, and HTML/TXT/VTT export cover the full review path. The default *Precise* model is a CTranslate2 conversion of Whisper large-v3-**turbo**. noScribe also accepts custom CTranslate2 models, allowing a controlled trial of [full large-v3](https://huggingface.co/Systran/faster-whisper-large-v3). Its mixed-language mode is explicitly experimental, and its own documentation warns that mixed speech can be translated instead of transcribed. The application is GPL-3.0, so a redistributed fork must comply with that license. [Usage](https://noscribe.de/en/docs/usage/), [Windows installation](https://noscribe.de/en/docs/download-installation/), [custom models](https://github.com/kaixxx/noScribe/wiki/Add-custom-Whisper-models-for-transcription), [repository](https://github.com/kaixxx/noScribe).

This ranks the **documented workflow and ability to test a suitable model**, not measured accuracy on your meetings. None of the applications below publishes a verified English/Filipino/Taglish meeting benchmark. The speech model, recording channels, human correction, and local test set will decide actual quality.

## Ranked workflows

| Rank | Workflow and pipeline | Windows, data path, maintenance, and fork tradeoff |
| --- | --- | --- |
| **1** | [noScribe](https://github.com/kaixxx/noScribe): import audio/video or a batch → local faster-whisper → pyannote speaker labels (known count can be set) → timestamps every minute or at speaker changes → audio-synced text editing → HTML, TXT, VTT. The *Multilingual* setting addresses mixed speech experimentally. [Usage](https://noscribe.de/en/docs/usage/), [editor source](https://github.com/kaixxx/noScribeEditor). | Native Windows CPU build; CUDA build requires RTX 20-series or newer and at least 6 GB VRAM. Runs locally. Current site documents 0.7; [releases](https://github.com/kaixxx/noScribe/releases) list 0.7.2. GPL-3.0. No built-in meeting capture; mixed-language translation and overlap remain quality risks. [Installation](https://noscribe.de/en/docs/download-installation/). |
| **2** | [Buzz](https://github.com/chidiwilliams/buzz): import files or record mic → local Whisper-family or other selectable ASR, with optional speech separation → speaker identification and timestamps → editable playback viewer → TXT, SRT, VTT. [Features](https://github.com/chidiwilliams/buzz), [editing](https://chidiwilliams.github.io/buzz/docs/usage/edit_and_resize). | MIT; Windows installer and active [releases](https://github.com/chidiwilliams/buzz/releases). Local engines keep processing on device; selecting an API engine sends audio to that service. Windows system-audio recording needs a virtual cable. Latest packaged release is 1.4.5, while some [CLI speaker-identification options](https://chidiwilliams.github.io/buzz/docs/cli) are documented for 1.4.6; check the installed version. [Recording](https://chidiwilliams.github.io/buzz/docs/usage/live_recording), [FAQ](https://chidiwilliams.github.io/buzz/docs/faq). |
| **3** | [TalkTrack](https://github.com/ObscureAintSecure/TalkTrack): record separate mic/system tracks → local faster-whisper with voice activity detection → channel labels or pyannote Community-1 speaker diarization → timestamped segments → playback, inline text/speaker edits → TXT, SRT, JSON. | MIT, Windows 10/11, CPU or optional CUDA. No packaged release or existing-file import was verified. Windows 11 per-app capture remains under development; system loopback is documented. Core speech processing is local, but choosing a hosted AI assistant can send transcript context to that provider. [Repository and limitations](https://github.com/ObscureAintSecure/TalkTrack). |
| **4** | [LocalScribe](https://github.com/imnotwallace/LocalScribe): capture mic plus meeting-app audio, or import → local Whisper → separate-channel merge and optional sherpa-ONNX speaker splitting → timestamped JSONL → layered text and speaker corrections/re-transcription → DOCX, Markdown, TXT, ZIP. [Workflow](https://github.com/imnotwallace/LocalScribe). | MIT, Windows 11. The packaged 0.9.0 is a first release; the bundled `tiny.en`/`base.en` models are English-only, while an optional multilingual large-v3-turbo download can handle Filipino in principle. Its documented application path is local; inspect any optional integrations before enabling them. Newer and more complex than the first two choices. [Repository](https://github.com/imnotwallace/LocalScribe). |
| **5** | [TranscriptionSuite](https://github.com/homelab-00/TranscriptionSuite): record mic/system audio or import a file → selectable local ASR including WhisperX → optional pyannote speakers for Whisper → timed transcript → TXT, SRT, ASS export. A transcript text editor was **not verified** in the official docs. [README and compatibility matrix](https://github.com/homelab-00/TranscriptionSuite). | GPLv3+, active [releases](https://github.com/homelab-00/TranscriptionSuite/releases). Windows uses an Electron dashboard plus Docker/Podman server; CPU and some GPU paths are documented. Windows Vulkan/whisper.cpp lacks diarization. Processing is local by default, while configured remote AI providers or outgoing webhooks can transmit text. Higher deployment burden for recorded-file correction. [Deployment](https://github.com/homelab-00/TranscriptionSuite/blob/main/docs/deployment-guide.md). |

If a permissive license is decisive, **Buzz is the first alternative**. If a small recorded-file codebase is preferable, [Local Transcriber](https://github.com/SFX-TECH/local-transcriber) is an MIT Windows/Docker option with faster-whisper, optional sherpa diarization, inline edits, and TXT/SRT/VTT/Markdown/JSON/DOCX export; it has a shorter maintenance history. [Project README](https://github.com/SFX-TECH/local-transcriber).

## Hugging Face models and pipeline components

Applications and models have separate licenses and requirements. A compatible model card does not prove a particular application supports that model without conversion or code changes.

| Component | Evidence and practical role | License, access, and quality gap |
| --- | --- | --- |
| [Whisper large-v3](https://huggingface.co/openai/whisper-large-v3) / [CTranslate2 conversion](https://huggingface.co/Systran/faster-whisper-large-v3) | Multilingual English/Tagalog (`tl`) ASR baseline; the conversion runs in faster-whisper and is the direct model swap to try in noScribe. Full model is about 3 GB of weights; CPU int8 is possible but slow for long meetings, so an NVIDIA GPU helps. [Model card](https://huggingface.co/openai/whisper-large-v3), [faster-whisper benchmarks and Windows notes](https://github.com/SYSTRAN/faster-whisper). | Original card says Apache-2.0; conversion card says MIT. Preserve upstream model attribution/terms when distributing weights. The model can hallucinate and code-switch accuracy is not established on spontaneous meetings. |
| [Whisper large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo) / [noScribe's documented CTranslate2 conversion](https://huggingface.co/mobiuslabsgmbh/faster-whisper-large-v3-turbo) | Faster default *Precise* path in noScribe; reduced decoder (32 to 4 layers) trades some recognition quality for speed. [Model card](https://huggingface.co/openai/whisper-large-v3-turbo), [noScribe install details](https://noscribe.de/en/docs/download-installation/). | MIT model card; no verified Taglish meeting comparison against full large-v3. Do not apply the full-model benchmark below to this turbo model. |
| [Qwen3-ASR-1.7B](https://huggingface.co/Qwen/Qwen3-ASR-1.7B) | Alternative ASR trial: its card lists English and Filipino (`fil`) and reports strong English AMI meeting results. A separate integration would be needed for noScribe; Windows installation is less established than faster-whisper. [Model card](https://huggingface.co/Qwen/Qwen3-ASR-1.7B). | Apache-2.0. Larger runtime/dependency burden; the companion [ForcedAligner](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B) does not list Filipino. English AMI results do not establish Taglish performance. |
| [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) | Local speaker diarization after download, with an optional GPU path and an *exclusive* output that helps reconcile speakers with transcript segments. Maintainer-reported AMI diarization error rate is 17.0% for IHM and 19.9% for SDM. [Model card](https://huggingface.co/pyannote/speaker-diarization-community-1). | CC-BY-4.0; gated weights require accepting conditions, sharing contact details, and a Hugging Face token. The AMI results concern diarization, not word recognition or Taglish meetings. The optional Precision-2 service processes audio on pyannote's cloud. |
| [Filipino XLS-R aligner](https://huggingface.co/Khalsuu/filipino-wav2vec2-l-xls-r-300m-official) | Current [WhisperX alignment code](https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py) maps `tl` to this model for word timing. | Apache-2.0. Its card omits training/evaluation detail; the existence of a Filipino aligner does not validate timings where English and Filipino switch within a sentence. |
| [MMS-1B-all](https://huggingface.co/facebook/mms-1b-all) | Has English and Tagalog language adapters; useful only as a comparison if its restriction fits the project. [Model card](https://huggingface.co/facebook/mms-1b-all). | **CC-BY-NC-4.0**, so it is a poor default for a fork that might be used commercially; separate adapters do not prove mixed-speech recognition. |

**Only preliminary Taglish evidence:** the [FilSwitch dataset card](https://huggingface.co/datasets/qwerttyuiiop/FilSwitch) self-reports 13.62% word error rate for pretrained **full** Whisper large-v3, 25.17% for Qwen3-ASR, and 26.41% for MMS on a speaker-disjoint 2.04-hour test set of **read Philippine news speech**. It reports 9.24% for a Whisper model fine-tuned on its training split; a release of that checkpoint was not verified. The study is marked under publication. Its stated 3,555 utterances differ from the page's 3,513 rows. These results support a first baseline choice, **not an expected meeting accuracy**. [Dataset card](https://huggingface.co/datasets/qwerttyuiiop/FilSwitch).

## Changes to test first

1. In noScribe, retain the original audio and compare its bundled turbo model with [full large-v3 in CTranslate2 format](https://huggingface.co/Systran/faster-whisper-large-v3), using the same local clips. Run transcription rather than translation and compare Auto with its experimental Multilingual setting. Its [custom-model instructions](https://github.com/kaixxx/noScribe/wiki/Add-custom-Whisper-models-for-transcription) require CTranslate2 format.
2. Keep mic and remote/system tracks separate at capture when available; test diarization with the known speaker count, then correct names and overlapping turns against playback. This is a proposed quality check, not a measured improvement. [noScribe speaker and editor controls](https://noscribe.de/en/docs/usage/), [TalkTrack dual-channel design](https://github.com/ObscureAintSecure/TalkTrack).
3. If word-level timing is required, trial WhisperX's Tagalog aligner on code-switched excerpts and manually inspect switch boundaries. Do not infer timing precision from its Tagalog mapping alone. [WhisperX alignment source](https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py).
4. Once consented recordings and human reference transcripts exist, evaluate a short stratified set covering English, Filipino, Taglish switches, overlap, silence, and proper names. Report WER by speech category and speaker-label errors separately. Only then decide whether a Qwen integration or Filipino/Taglish fine-tuning earns its added burden.

## Search and verification limits

Searches on 4 October 2026 covered GitHub repositories and project documentation, Hugging Face model cards and Spaces, GitLab, and Codeberg. Screening required accessible source, an identifiable license, and a documented local or self-hosted path. [Hugging Face Spaces search](https://huggingface.co/spaces?includeNonRunning=true&p=0&q=whisper&sort=relevance) yielded demos/hosted flows rather than a better verified local Windows editing workflow. The [GitLab Amanu lead](https://gitlab.com/varg.alejandro25/amanu) lacked verifiable license and pipeline details, so it was excluded. Codeberg blocked automated inspection, leaving a coverage gap. No application was installed and no audio was uploaded. Repository feature claims and maintainer benchmarks were checked against linked primary pages; real Windows behavior and target-language quality still need hands-on validation.
