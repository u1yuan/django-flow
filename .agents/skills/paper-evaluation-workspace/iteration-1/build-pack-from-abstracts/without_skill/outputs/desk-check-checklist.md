# Desk-check checklist

Desk-checking in this pack is a **checklist-guided self-review before check-in**. It is **not** a structured inspection (CASE abstract).

Use this list on a paper or on this pack before scores are checked in. Tick each item. Separate **feasibility** from **acceptance** (CASE). Do not treat PLAN as a validated framework.

Paper or artifact: ______________________
Reviewer: ai-draft
Date: __________

## Identity and sources

- [ ] The text under review is identified (PLAN, CASE, or another paper).
- [ ] Criteria used for scoring are traced to PLAN and/or CASE abstracts (`source-trace.md`).
- [ ] No criterion is tagged `full-text` unless a body was actually read.
- [ ] SYNTHETIC sources are not cited as real publications.

## PLAN-derived checks (model comparison / QA guidelines)

- [ ] QA guidelines for the **model-building phase** are present, planned, or explicitly marked absent.
- [ ] Quality-task processes are considered **at each phase**, or the gap is stated.
- [ ] Model-performance reporting is judged for **model comparison**, not only for a single-model write-up.
- [ ] If a literature study is claimed, it is labeled planned vs completed.
- [ ] If expert validation is named, it is labeled a **method item** only. Planned expert validation does not validate a framework.
- [ ] If a pilot is named, the **two development teams** requirement is checked.
- [ ] Results vs plan: "No results are reported" is respected for PLAN.

## CASE-derived checks (desk-checking and variability)

- [ ] Feasibility is answered as its own question.
- [ ] Acceptance is answered as its own question.
- [ ] Variability-model creation is recognized as a QA process part.
- [ ] Desk-checking is described as checklist-guided self-review before check-in.
- [ ] Desk-checking is **not** recoded as a structured inspection.
- [ ] Variant coverage: can the modeling language represent all important variants? If not, the limit is written down.
- [ ] Developer acceptance is recorded for **both** parts (variability-model creation and desk-checking) when both are in scope.
- [ ] Study limits are reported.

## Adapted checks

- [ ] The QA process is split into identifiable parts.
- [ ] Claim type matches evidence (plan vs case study).
- [ ] The PLAN framework is **not** called validated.

## Check-in gate

- [ ] Reviewer label is `ai-draft` (unless a later human review replaces this draft).
- [ ] Scores use 0 / 1 / 2 or `NA`.
- [ ] Justifications quote or paraphrase the SYNTHETIC abstracts without inventing results.
- [ ] Ready to check in.
